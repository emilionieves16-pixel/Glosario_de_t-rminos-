    fork(), waitpid() y strace

    El padre crea un hijo, este termina con código 42 y el padre recoge su estado. strace -f sigue también al hijo y muestra que Linux materializa fork() con clone y la espera con wait4.

    Ver código fuente: fork_wait.c
    C · fork_wait.c
    #define _POSIX_C_SOURCE 200809L
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        return EXIT_FAILURE;
    }
    if (pid == 0) {
        printf("hijo:  pid=%ld, ppid=%ld\n", (long)getpid(), (long)getppid());
        fflush(stdout);
        _exit(42);
    }

    printf("padre: pid=%ld, hijo=%ld\n", (long)getpid(), (long)pid);
    fflush(stdout);

    int status;
    pid_t seen;
    do {
        seen = waitpid(pid, &status, 0);
    } while (seen < 0 && errno == EINTR);

    if (seen < 0) {
        perror("waitpid");
        return EXIT_FAILURE;
    }
    if (WIFEXITED(status))
        printf("padre: waitpid=%ld, exit=%d\n", (long)seen, WEXITSTATUS(status));
    return WIFEXITED(status) && WEXITSTATUS(status) == 42 ? EXIT_SUCCESS : EXIT_FAILURE;
}

    pthreads y mutex: una carrera medible

    Cuatro hilos realizan 250.000 incrementos cada uno. Al compilar con -DRACE se eliminan lock/unlock y la operación ++counter deja de ser indivisible lógicamente; el resultado depende del entrelazado.

    Ver código fuente: pthread_mutex.c
    C · pthread_mutex.c
    #include <pthread.h>
#include <stdio.h>
#include <stdlib.h>

#define THREADS 4
#define STEPS 250000

static long counter;
static pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

static void fail(int rc, const char *what) {
    if (rc) {
        fprintf(stderr, "%s: código %d\n", what, rc);
        exit(EXIT_FAILURE);
    }
}

static void *worker(void *unused) {
    (void)unused;
    for (long i = 0; i < STEPS; ++i) {
#ifndef RACE
        fail(pthread_mutex_lock(&lock), "pthread_mutex_lock");
#endif
        ++counter; /* sección crítica: lectura, incremento y escritura */
#ifndef RACE
        fail(pthread_mutex_unlock(&lock), "pthread_mutex_unlock");
#endif
    }
    return NULL;
}

int main(void) {
    pthread_t ids[THREADS];
    for (long i = 0; i < THREADS; ++i)
        fail(pthread_create(&ids[i], NULL, worker, NULL), "pthread_create");
    for (size_t i = 0; i < THREADS; ++i)
        fail(pthread_join(ids[i], NULL), "pthread_join");
    printf("contador=%ld, esperado=%ld\n", counter, (long)THREADS * STEPS);
    fail(pthread_mutex_destroy(&lock), "pthread_mutex_destroy");
    return counter == (long)THREADS * STEPS ? EXIT_SUCCESS : EXIT_FAILURE;
}
    Versión protegida
    $ gcc -std=c11 -Wall -Wextra -Wpedantic -O0 -g -pthread pthread_mutex.c -o pthread_mutex
$ ./pthread_mutex
contador=1000000, esperado=1000000
    Versión con carrera deliberada
    $ gcc -std=c11 -Wall -Wextra -Wpedantic -O0 -g -pthread -DRACE pthread_mutex.c -o pthread_race
$ ./pthread_race
contador=514293, esperado=1000000
exit=1

    El valor de la carrera no es una cota ni un resultado garantizado: otra ejecución puede producir otro número. La versión con mutex conserva el invariante.

    Valgrind Memcheck: acceso inválido y fuga

int main(void) {
    int *p = malloc(4 * sizeof *p); /* reserva p[0]..p[3] */
    if (!p)
        return EXIT_FAILURE;
    for (int i = 0; i < 4; ++i)
        p[i] = i;
    p[4] = 99; /* ERROR deliberado: escritura fuera del bloque */
    printf("valor inválido=%d\n", p[4]); /* ERROR deliberado: lectura inválida */
    p = NULL; /* la única referencia se pierde: fuga de 16 bytes */

    Lectura de la cadena MMU → TLB → Page Fault → Swap → Thrashing

    La MMU consulta primero la TLB. Un acierto evita el recorrido; un fallo de TLB consulta las tablas y solo deriva en page fault si la entrada no puede resolver el acceso. El manejador puede traer contenido desde swap, zRAM o zswap. Si el working set excede los marcos disponibles, los reemplazos provocan fallos repetidos y el sistema entra en thrashing.

      Glosario de Sistemas Operativos

      1. Sistema operativo

      Operating system (OS) · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Software que administra los recursos físicos de una computadora y ofrece a los programas un entorno de ejecución, servicios e interfaces bien definidas. Coordina procesos, memoria, almacenamiento, dispositivos, protección y comunicación entre componentes.

      Rol operativo / utilidad

      Actúa como árbitro entre cargas que compiten por recursos y como máquina extendida: simplifica el hardware, impone aislamiento y procura utilización, continuidad y seguridad del servicio.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 1, «Introduction», §§1.1 y 1.4–1.6). Wiley.

      2. Núcleo

      Kernel · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Parte privilegiada y normalmente residente del sistema operativo que implementa los mecanismos esenciales de ejecución, memoria, planificación, interrupciones y acceso a dispositivos. Su alcance exacto depende de la arquitectura monolítica, híbrida o de micronúcleo.

      Rol operativo / utilidad

      Concentra el control del hardware y media las operaciones sensibles; sus decisiones determinan el aislamiento entre procesos y buena parte del rendimiento y la fiabilidad del sistema.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 1, «Introduction», §1.4; cap. 2, «Operating-System Structures», §2.7). Wiley.

      3. Árbitro de recursos

      Resource arbiter · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Función del sistema operativo mediante la cual adjudica CPU, memoria, ancho de banda de E/S y otros recursos compartidos entre solicitantes concurrentes. Combina mecanismos de contabilidad, políticas de asignación y reglas de prioridad o equidad.

      Rol operativo / utilidad

      Evita que una carga monopolice el equipo, resuelve competencia y aplica objetivos de rendimiento, calidad de servicio y aislamiento mediante planificación, cuotas y límites.

      Cita APA

      Tanenbaum, A. S., & Bos, H. (2015). Modern operating systems (4.ª ed.; cap. 1, «Introduction», §1.1.2, «The Operating System as a Resource Manager»). Pearson.

      4. Máquina extendida

      Extended machine · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Visión del sistema operativo como una abstracción que presenta al programador una máquina más simple y uniforme que el hardware real. Procesos, archivos, memoria virtual y sockets sustituyen detalles de registros, controladores y dispositivos concretos.

      Rol operativo / utilidad

      Reduce la complejidad de programar y facilita reutilización y portabilidad; ofrece servicios de alto nivel sin exponer a cada aplicación a las particularidades físicas del equipo.

      Cita APA

      Tanenbaum, A. S., & Bos, H. (2015). Modern operating systems (4.ª ed.; cap. 1, «Introduction», §1.1.1, «The Operating System as an Extended Machine»). Pearson.

      5. Abstracción de hardware

      Hardware abstraction · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Separación entre las propiedades visibles de un recurso y los detalles de su implementación física, expresada mediante interfaces estables como archivos, descriptores, direcciones virtuales o APIs de dispositivo. No implica ocultar necesariamente el costo de la operación.

      Rol operativo / utilidad

      Permite que controladores, VFS y subsistemas del núcleo integren hardware diverso sin cambiar las aplicaciones, además de centralizar validación, sincronización y control de acceso.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 2, «Operating-System Structures», §§2.1 y 2.6; cap. 12, «I/O Systems», §12.3). Wiley.

      6. Modo usuario

      User mode · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Estado de ejecución con privilegios restringidos en el que el procesador impide ejecutar instrucciones sensibles y limita las regiones de memoria accesibles. Las aplicaciones solicitan servicios privilegiados mediante llamadas al sistema, excepciones o interrupciones.

      Rol operativo / utilidad

      Contiene errores y acciones maliciosas dentro del espacio del proceso; obliga a que todo acceso crítico cruce una puerta controlada por el núcleo.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 1, «Introduction», §1.4.1, «Dual-Mode and Multimode Operation»). Wiley.

      7. Modo núcleo

      Kernel mode · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Estado de ejecución privilegiado que habilita el conjunto completo de instrucciones y el acceso a estructuras protegidas del procesador y del sistema operativo. En él se ejecutan el núcleo y, según la arquitectura, controladores y manejadores de eventos.

      Rol operativo / utilidad

      Permite cambiar tablas de páginas, configurar dispositivos y arbitrar recursos; exige código confiable porque un fallo puede comprometer todo el sistema.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 1, «Introduction», §1.4.1, «Dual-Mode and Multimode Operation»). Wiley.

      8. Anillos de protección

      Protection rings · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Modelo jerárquico de dominios de privilegio, representado en x86 por niveles numerados del 0 al 3. Los mecanismos de segmentación, descriptores y puertas restringen el acceso a código y datos y controlan las transiciones entre niveles.

      Rol operativo / utilidad

      Separa núcleo y aplicaciones y puede alojar dominios intermedios; complementa la protección de memoria al impedir elevaciones de privilegio no mediadas.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 17, «Protection», §17.3, «Protection Rings»). Wiley.

      9. Anillo 0

      Ring 0 · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Nivel de máximo privilegio en el modelo de anillos x86, utilizado habitualmente por el núcleo. Puede ejecutar instrucciones privilegiadas y acceder a recursos cuyos descriptores exigen ese nivel, sujeto también a los demás controles del procesador.

      Rol operativo / utilidad

      Hospeda las operaciones que configuran memoria, interrupciones y dispositivos; su separación respecto del anillo 3 es una barrera esencial de seguridad.

      Cita APA

      Intel Corporation (s. f.). Intel® 64 and IA-32 architectures software developer’s manual (vol. 3A, cap. 5, «Protection», §§5.5–5.6). Intel.

      10. Anillo 3

      Ring 3 · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Nivel de menor privilegio del modelo x86, destinado normalmente a aplicaciones. Sus referencias a memoria y transferencias de control se comprueban contra los niveles de privilegio, y las instrucciones sensibles provocan una excepción si no están permitidas.

      Rol operativo / utilidad

      Ejecuta código no confiable con autoridad mínima y dirige sus solicitudes al núcleo mediante interfaces controladas, reduciendo el alcance de fallos y ataques.

      Cita APA

      Intel Corporation (s. f.). Intel® 64 and IA-32 architectures software developer’s manual (vol. 3A, cap. 5, «Protection», §§5.5–5.6). Intel.

      11. Llamada al sistema

      System call (syscall) · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Interfaz programada por la que un proceso solicita un servicio del núcleo mediante una entrada controlada y una convención de argumentos definida por la ABI. El núcleo valida la petición, ejecuta la operación autorizada y devuelve un resultado o error.

      Rol operativo / utilidad

      Es la frontera operativa entre usuario y núcleo para crear procesos, acceder a archivos, reservar memoria o comunicar tareas, sin conceder privilegios generales a la aplicación.

      Cita APA

      Kerrisk, M. (2010). The Linux programming interface: A Linux and UNIX system programming handbook (cap. 3, «System Programming Concepts», §3.1, «System Calls»). No Starch Press.

      12. Interrupción de hardware

      Hardware interrupt · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Señal asíncrona originada por un dispositivo, controlador o temporizador que solicita atención del procesador. Tras identificar el vector y preservar el estado necesario, el hardware transfiere el control a la rutina asociada, que después puede reanudar la ejecución.

      Rol operativo / utilidad

      Evita esperar activamente a los dispositivos, marca trabajo pendiente y permite al núcleo responder a E/S y reloj con baja latencia.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 1, «Introduction», §1.2.1, «Interrupts»; cap. 12, «I/O Systems», §12.2). Wiley.

      13. Interrupción de software

      Software interrupt (trap) · Módulo 1: Fundamentos, arquitectura y arranque

      Definición formal

      Transferencia al núcleo provocada por una instrucción o condición síncrona del programa, como una excepción, un punto de ruptura o una instrucción específica de llamada. A diferencia de una interrupción externa, está relacionada con la instrucción que se ejecuta.

      Rol operativo / utilidad

      Implementa entradas deliberadas a servicios privilegiados y el tratamiento de errores, depuración y eventos excepcionales con preservación del contexto.

      Cita APA

      49. Espacio de núcleo

      Definición formal

      Dominio privilegiado de memoria y ejecución reservado al núcleo y a sus estructuras compartidas. Su disposición en el mapa de direcciones depende de la arquitectura y de mitigaciones de seguridad; no debe confundirse con la memoria privada de una aplicación.

      51. Proceso

      Definición formal

      Instancia de un programa en ejecución representada por un espacio de direcciones, uno o más hilos, credenciales, descriptores y demás recursos administrados por el sistema. El programa almacenado es pasivo; el proceso incorpora estado dinámico y contexto de ejecución.

      Rol operativo / utilidad

      Es la unidad principal de aislamiento y contabilidad: el núcleo lo crea, planifica sus hilos, limita sus accesos y recupera sus recursos al finalizar.

      Definición formal

      Organización del espacio de direcciones de un proceso en regiones como texto, datos inicializados, BSS, heap, pilas y mapeos de bibliotecas o archivos. Es una disposición lógica; las páginas pueden residir en RAM o estar aún sin materializar.

      Rol operativo / utilidad

      Permite al cargador y al núcleo aplicar permisos, crecimiento y residencia por región, además de compartir páginas y diagnosticar consumo con herramientas como pmap.

      Rol operativo / utilidad

      Rol operativo / utilidad

      Definición formal

      Estado de una tarea que puede ejecutarse pero no ocupa actualmente una CPU porque el planificador ha seleccionado otra. Sus recursos esenciales están disponibles y permanece en las estructuras de tareas ejecutables del sistema.

      Rol operativo / utilidad

      Alimenta la cola de selección del planificador; el tiempo acumulado aquí explica espera de CPU y orienta decisiones de equidad y prioridad.

      Definición formal

      Estado en el que un hilo tiene asignada una CPU lógica y ejecuta instrucciones, ya sea en modo usuario o núcleo. En un multiprocesador puede haber tantos hilos ejecutándose como unidades de ejecución disponibles.

      Rol operativo / utilidad

      Representa el consumo efectivo de procesador; el núcleo contabiliza este tiempo y puede abandonarlo por apropiación, bloqueo o terminación.

      Definición formal

      Estado en el que una tarea no puede avanzar hasta que ocurra un evento, como completarse E/S, liberarse un mutex o llegar un mensaje. Mientras espera no compite por la CPU y será despertada por el subsistema correspondiente.

      Rol operativo / utilidad

      Evita consumo inútil de procesador durante esperas y conecta la finalización de eventos con la reactivación oportuna de trabajo.

      Estado alcanzado cuando un proceso ha concluido su ejecución de forma normal o anormal. Ya no ejecuta instrucciones; el núcleo libera la mayoría de recursos, aunque puede conservar temporalmente su estado de salida para el padre.

      Rol operativo / utilidad

      Preserva el resultado para la sincronización padre-hijo; una acumulación indica que la aplicación no cosecha hijos y puede agotar entradas o identificadores.

      Definición formal

      Proceso cuyo padre termina antes que él. No queda sin control: en UNIX es adoptado por init o, en Linux, por el subreaper más cercano configurado, que recibe después sus cambios de estado.

      Garantiza que siempre exista un responsable de cosechar el estado final y mantiene coherente el árbol de procesos, incluso en daemons y contenedores.

      Definición formal

      Región que contiene variables globales y estáticas con valores iniciales explícitos almacenados en el archivo ejecutable. Al cargar el programa se establece un mapeo escribible cuyas páginas privadas pueden copiarse al modificarse.

      Rol operativo / utilidad

      Conserva estado persistente durante toda la ejecución del proceso y separa datos mutables del código para aplicar permisos y compartición adecuados.

      Definición formal

      Región destinada a variables globales y estáticas sin inicializador explícito, que el lenguaje exige iniciar en cero. El ejecutable suele registrar su tamaño, no una copia completa de todos sus bytes.

      Rol operativo / utilidad

      Ahorra espacio en disco: el cargador y la memoria virtual proporcionan páginas cero al materializar la región, manteniendo semántica de inicialización.

      Definición formal

      Región de crecimiento y contracción dinámica organizada en marcos de llamada, con direcciones de retorno, registros preservados y variables automáticas. Cada hilo posee su propia pila; su tamaño y crecimiento están limitados por reglas del sistema.

      Sostiene el flujo de llamadas y el contexto local con asignación muy barata; guard pages y límites ayudan a detectar desbordamientos.

      Definición formal

      Área de memoria dinámica del proceso utilizada por asignadores como malloc para objetos cuya vida no está ligada a un marco de pila. La biblioteca puede ampliarla con brk o atender reservas mediante mmap, según tamaño y estrategia.

      Rol operativo / utilidad

      Ofrece almacenamiento flexible bajo control de la aplicación; el núcleo materializa y protege las páginas, mientras fragmentación y fugas inciden en consumo real.

      66. Cambio de contexto

      Definición formal

      Operación por la que el núcleo guarda el estado de una tarea y restaura el de otra en una CPU. Incluye registros y estado de planificación y, si cambia el espacio de direcciones, acciones adicionales de memoria y traducción.

      Rol operativo / utilidad

      Implementa multiprogramación y apropiación, pero consume trabajo no productivo y puede alterar cachés y TLB; su frecuencia se equilibra con la capacidad de respuesta.

      Definición formal

      Costo temporal y microarquitectónico de detener una tarea, administrar estructuras del núcleo y reanudar otra. Además de guardar registros, puede incluir pérdida de localidad en cachés, TLB y predictores, cuyo efecto depende de la carga.

      Definición formal

      Rol operativo / utilidad

      Convierte un proceso recién creado en el programa solicitado y establece una nueva pila, código y datos sin crear otro PID.

      Definición formal

      Llamada que permite esperar o consultar cambios de estado de procesos hijos seleccionados por PID o grupo y recuperar su condición de terminación. Sus opciones controlan bloqueo, procesos detenidos y consulta sin espera.

      Definición formal

      Flujo de ejecución planificable dentro de un proceso, con contador de programa, registros y pila propios, que comparte el espacio de direcciones y muchos recursos con otros hilos del mismo proceso. La representación exacta varía según el sistema.

      Rol operativo / utilidad

      Permite concurrencia y comunicación de bajo costo dentro de una aplicación; el núcleo lo planifica y la sincronización evita interferencias sobre datos compartidos.

      Definición formal

      Hilos gestionados principalmente por una biblioteca en espacio de usuario, sin que cada uno tenga necesariamente una entidad homóloga planificable por el núcleo. En un modelo muchos-a-uno, una llamada bloqueante puede detener todo el conjunto.

      Rol operativo / utilidad

      Definición formal

      Capacidad de estructurar varias actividades que progresan de forma solapada y cuyos órdenes relativos no están completamente predeterminados. Puede implementarse alternando tareas en una CPU y no implica ejecución física simultánea.

      Rol operativo / utilidad

      Mejora capacidad de respuesta y aprovechamiento de esperas; obliga al núcleo y a las aplicaciones a coordinar accesos, eventos y orden visible de operaciones.

      Definición formal

      Ejecución efectivamente simultánea de operaciones en distintas unidades de procesamiento. El paralelismo de datos reparte conjuntos de datos y el de tareas distribuye actividades; su beneficio está limitado por dependencias y por la parte serial de la carga.

      Rol operativo / utilidad

      Aumenta throughput y reduce tiempo de cómputo cuando hay trabajo independiente; el planificador y la memoria compartida determinan cuánto paralelismo potencial se materializa.

      Definición formal

      Fragmento de código en el que una tarea accede a un recurso o estado compartido cuya invariante puede romperse por ejecución concurrente no coordinada. El problema exige exclusión cuando corresponda, progreso y espera limitada.

      Rol operativo / utilidad

      Delimita lo que debe protegerse con mutexes u otros mecanismos; mantenerla breve reduce contención y disminuye el tiempo durante el cual otros hilos quedan bloqueados.

      Definición formal

      Propiedad que garantiza que como máximo una tarea ejecuta una sección crítica asociada al mismo recurso en un instante dado. Se obtiene mediante cerraduras, semáforos, monitores o técnicas especializadas, respetando además progreso y equidad.

      Rol operativo / utilidad

      Conserva invariantes sobre objetos compartidos y serializa operaciones incompatibles; una granularidad excesiva puede convertirla en cuello de botella.

      Rol operativo / utilidad

      Explica errores intermitentes y corrupción de datos; se combate identificando conflictos y estableciendo sincronización y relaciones de orden, no repitiendo pruebas hasta que desaparezcan.

      Counting semaphore (sem_t) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Primitiva entera cuyas operaciones atómicas wait y post representan adquisición y liberación de unidades de un recurso o eventos acumulables. sem_t es el tipo POSIX; su valor inicial expresa cuántas adquisiciones pueden ocurrir sin bloquear.

      Rol operativo / utilidad

      Controla conjuntos de recursos y cotas de concurrencia, como buffers con ranuras libres y ocupadas, sin depender de una única propiedad de hilo.

      Cita APA

      Kerrisk, M. (2010). The Linux programming interface: A Linux and UNIX system programming handbook (cap. 53, «POSIX Semaphores», §§53.1–53.4). No Starch Press.

      84. Operación sem_wait

      sem_wait() operation · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Operación POSIX que intenta decrementar atómicamente un semáforo y, si su valor es cero, suspende al llamante hasta que pueda completarse la adquisición. Puede fallar o ser interrumpida según las condiciones especificadas por POSIX.

      Rol operativo / utilidad

      Hace esperar a consumidores o solicitantes sin sondeo activo y reserva una unidad antes de acceder al recurso protegido.

      Cita APA

      Kerrisk, M. (2010). The Linux programming interface: A Linux and UNIX system programming handbook (cap. 53, «POSIX Semaphores», §53.4, «Semaphore Operations»). No Starch Press.

      85. Operación sem_post

      sem_post() operation · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Operación POSIX que incrementa atómicamente un semáforo y, si hay hilos esperando, permite que uno continúe según la implementación. No exige que el llamante haya ejecutado previamente sem_wait sobre ese mismo semáforo.

      Rol operativo / utilidad

      Publica disponibilidad o un evento y despierta trabajo pendiente; junto con sem_wait forma el mecanismo básico de conteo y señalización.

      Cita APA

      Kerrisk, M. (2010). The Linux programming interface: A Linux and UNIX system programming handbook (cap. 53, «POSIX Semaphores», §53.4, «Semaphore Operations»). No Starch Press.

      86. Monitor de sincronización

      Synchronization monitor · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Abstracción de alto nivel que agrupa datos compartidos y procedimientos cuya ejecución se realiza con exclusión implícita, junto con variables de condición para esperar predicados. Lenguajes y bibliotecas pueden ofrecer construcciones con semánticas distintas.

      Rol operativo / utilidad

      Encapsula la sincronización cerca del estado protegido y reduce olvidos de liberación; las esperas deben seguir comprobando su condición en un bucle.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 6, «Synchronization Tools», §6.7, «Monitors»). Wiley.

      87. Variable de condición

      Condition variable · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Primitiva que permite a un hilo esperar hasta que otro señalice que un predicado pudo cambiar. La espera libera atómicamente el mutex asociado y lo readquiere antes de retornar; una señal no garantiza que el predicado sea verdadero.

      Rol operativo / utilidad

      Evita espera activa cuando no puede avanzarse y coordina productores y consumidores; el predicado se reevalúa siempre en un bucle por despertares espurios o múltiples consumidores.

      Cita APA

      Kerrisk, M. (2010). The Linux programming interface: A Linux and UNIX system programming handbook (cap. 30, «Threads: Thread Synchronization», §30.2, «Signaling Changes of State: Condition Variables»). No Starch Press.

      88. Cerradura giratoria

      Spinlock · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Cerradura cuya adquisición espera activamente mediante operaciones atómicas hasta que queda libre, sin suspender al solicitante. Resulta apropiada para esperas muy breves y para contextos del núcleo donde dormir está prohibido.

      Rol operativo / utilidad

      Evita el costo de bloquear y despertar cuando la sección crítica es corta, pero consume CPU y puede agravar inversión de prioridades si se retiene demasiado.

      Cita APA

      Love, R. (2010). Linux kernel development (3.ª ed.; cap. 10, «Kernel Synchronization Methods», sección «Spin Locks»). Addison-Wesley.

      89. Interbloqueo

      Deadlock · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Situación en la que un conjunto de tareas queda esperando indefinidamente recursos retenidos por otras tareas del mismo conjunto. No equivale a una ejecución lenta: ninguna de las involucradas puede progresar sin intervención o cambio de asignación.

      Rol operativo / utilidad

      Paraliza trabajo y retiene recursos; el sistema debe prevenirlo, evitarlo o detectarlo y recuperarse mediante terminación, revocación o reinicio según la política.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §§8.1–8.2). Wiley.

      90. Condiciones de Coffman

      Coffman conditions · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Cuatro condiciones necesarias para un interbloqueo con recursos reutilizables: exclusión mutua, retención y espera, no apropiación y espera circular. Su presencia conjunta caracteriza la posibilidad; romper al menos una impide que se forme un deadlock.

      Rol operativo / utilidad

      Ofrecen una guía sistemática de prevención: compartir cuando sea seguro, reservar conjuntamente, permitir revocación o imponer un orden global de recursos.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §8.2.2, «Deadlock Characterization»). Wiley.

      91. Retención y espera

      Hold and wait · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Condición en la que una tarea conserva al menos un recurso mientras solicita otros actualmente asignados. La espera no libera los recursos ya obtenidos, por lo que puede cerrar una cadena de dependencias.

      Rol operativo / utilidad

      Explica la acumulación de bloqueos; se previene solicitando todos los recursos a la vez o exigiendo liberar los poseídos antes de pedir nuevos.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §8.2.2; §8.5, «Deadlock Prevention»). Wiley.

      92. No apropiación

      No preemption · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Condición según la cual un recurso no puede ser retirado forzosamente a su poseedor y solo se libera voluntariamente al completar su uso. Es inherente a ciertos recursos cuya revocación dejaría un estado inconsistente.

      Rol operativo / utilidad

      Mantiene dependencias durante la espera; permitir apropiación puede evitar deadlocks, pero exige guardar y restaurar estado o repetir operaciones de forma segura.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §8.2.2; §8.5.3, «No Preemption»). Wiley.

      93. Espera circular

      Circular wait · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Condición en la que existe una cadena cerrada de tareas tal que cada una espera un recurso retenido por la siguiente. Con recursos de una sola instancia, el ciclo en el grafo de asignación evidencia el interbloqueo.

      Rol operativo / utilidad

      Cierra la dependencia que impide progresar; una ordenación total de tipos de recurso y adquisición creciente elimina esta condición.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §8.2.2; §8.5.4, «Circular Wait»). Wiley.

      94. Grafo de asignación de recursos

      Resource-allocation graph (RAG) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Grafo dirigido con vértices de procesos y recursos y aristas de solicitud y asignación. Modela instancias mediante puntos; un ciclo es necesario para deadlock, pero con múltiples instancias no siempre es suficiente.

      Rol operativo / utilidad

      Permite visualizar dependencias y aplicar detección o evitación; el núcleo o una herramienta puede usarlo para decidir si una asignación conduce a un estado seguro.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §8.2.2, «Resource-Allocation Graph»). Wiley.

      95. Prevención de interbloqueos

      Deadlock prevention · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Conjunto de métodos estructurales que garantizan la ausencia de deadlocks negando al menos una condición de Coffman en toda ejecución. A diferencia de la evitación, no requiere estimar el estado seguro antes de cada solicitud.

      Rol operativo / utilidad

      Aporta una garantía por diseño, aunque puede reducir utilización o concurrencia al exigir reservas totales, revocación u órdenes estrictos de cerraduras.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §8.5, «Deadlock Prevention»). Wiley.

      96. Detección de interbloqueos

      Deadlock detection · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Estrategia que permite que las dependencias se formen y examina periódicamente asignaciones y solicitudes para identificar tareas bloqueadas permanentemente. Debe complementarse con una política de recuperación y considerar el costo de cada análisis.

      Rol operativo / utilidad

      Mantiene mayor flexibilidad que la prevención; al detectar, el administrador o el sistema puede terminar tareas o revocar recursos minimizando pérdida de trabajo.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §8.6, «Deadlock Detection»; §8.7, «Recovery from Deadlock»). Wiley.

      97. Algoritmo del banquero

      Banker's algorithm · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Algoritmo de evitación que conoce la demanda máxima declarada de cada proceso y concede una solicitud solo si el estado resultante es seguro. Simula una secuencia en la que todos pueden terminar; un estado inseguro no implica que ya exista deadlock.

      Rol operativo / utilidad

      Evita asignaciones de las que no habría salida garantizada, a costa de información previa, reservas conservadoras y una secuencialización de decisiones poco práctica en muchos sistemas generales.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 8, «Deadlocks», §8.4.3, «Banker’s Algorithm»). Wiley.

      98. Inanición

      Starvation · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Espera indefinida de una tarea que permanece apta o solicitante mientras otras obtienen repetidamente el recurso. Puede deberse a prioridades, órdenes de servicio o ráfagas continuas, aunque el sistema global siga progresando.

      Rol operativo / utilidad

      Degrada equidad y puede impedir que trabajos terminen; técnicas como envejecimiento, herencia de prioridad y cuotas limitan el aplazamiento indefinido.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 6, «Synchronization Tools», §6.8, «Liveness»). Wiley.

      99. Inversión de prioridades

      Priority inversion · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Situación en la que una tarea de alta prioridad espera un recurso retenido por otra de menor prioridad y tareas intermedias impiden que esta última avance. El orden efectivo de ejecución contradice la urgencia prevista.

      Rol operativo / utilidad

      Puede violar plazos en sistemas en tiempo real; la herencia o el techo de prioridad elevan temporalmente al poseedor para acotar el bloqueo.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 6, «Synchronization Tools», §6.8.2, «Priority Inversion»). Wiley.

      100. Planificación de CPU

      CPU scheduling · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Actividad que selecciona qué hilo ejecutable ocupará cada CPU y durante cuánto tiempo, aplicando políticas de equidad, prioridad, plazos o eficiencia. Actúa al bloquearse, terminar, despertar o apropiarse tareas y coopera con la gestión multinúcleo.

      Rol operativo / utilidad

      Arbitra el recurso procesador y determina utilización, respuesta y cumplimiento temporal; ninguna métrica aislada describe la calidad de todas las cargas.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §§5.1–5.3). Wiley.

      101. Primero en llegar, primero en ser servido

      First-Come, First-Served (FCFS) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Algoritmo no apropiativo que atiende las tareas en orden de llegada hasta que ceden la CPU o terminan. Es simple de implementar con una cola FIFO y no considera la duración de la próxima ráfaga.

      Rol operativo / utilidad

      Reduce decisiones de planificación, pero puede provocar efecto convoy: trabajos cortos esperan detrás de uno largo, deteriorando espera y respuesta promedio.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.3.1, «First-Come, First-Served Scheduling»). Wiley.

      102. Turno rotatorio

      Round Robin (RR) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Algoritmo apropiativo que recorre una cola FIFO y asigna a cada tarea un cuanto; si no termina su ráfaga, vuelve al final de la cola. Su comportamiento depende críticamente de la relación entre cuanto, ráfagas y costo de conmutación.

      Rol operativo / utilidad

      Reparte CPU con equidad y mejora respuesta interactiva; cuantos extremos aumentan sobrecarga o reproducen el efecto de FCFS.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.3.2, «Round-Robin Scheduling»). Wiley.

      103. Trabajo más corto primero

      Shortest-Job-First (SJF) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Política que selecciona la tarea con la próxima ráfaga de CPU más corta, en su versión no apropiativa. Es óptima para minimizar el tiempo de espera promedio cuando todas las ráfagas se conocen, condición que normalmente debe estimarse.

      Rol operativo / utilidad

      Favorece trabajos cortos y mejora promedios teóricos, pero necesita predicción y puede postergar indefinidamente ráfagas largas si llegan cortas continuamente.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.3.3, «Shortest-Job-First Scheduling»). Wiley.

      104. Tiempo restante más corto primero

      Shortest-Remaining-Time-First (SRTF) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Variante apropiativa de SJF en la que una llegada o cambio de estimación puede desplazar al proceso actual si otra tarea tiene menor tiempo restante. Requiere comparar la ráfaga restante, no la duración total original.

      Rol operativo / utilidad

      Reduce espera de trabajos cortos con respuesta oportuna, pero incrementa conmutaciones y comparte los riesgos de predicción e inanición de SJF.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.3.3, «Shortest-Job-First Scheduling»). Wiley.

      105. Colas multinivel

      Multilevel queues · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Esquema que divide los procesos en colas según atributos como prioridad o tipo de carga, cada una con su propio algoritmo. Una política adicional decide entre colas; en la variante básica los procesos no cambian de clase dinámicamente.

      Rol operativo / utilidad

      Adapta la planificación a cargas interactivas y por lotes y simplifica la selección dentro de cada grupo, aunque una mala política entre colas puede causar inanición.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.3.5, «Multilevel Queue Scheduling»). Wiley.

      106. Colas multinivel con retroalimentación

      Multilevel Feedback Queue (MLFQ) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Extensión de colas multinivel que permite mover tareas entre prioridades según su comportamiento observado. Suele favorecer trabajos nuevos o interactivos y degradar quienes consumen su cuanto, con reglas para evitar inanición y manipulación.

      Rol operativo / utilidad

      Aproxima buena respuesta sin conocer ráfagas futuras y aprende del uso real de CPU; el diseño debe incluir envejecimiento y contabilidad global adecuada.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.3.6, «Multilevel Feedback Queue Scheduling»). Wiley.

      107. Planificador completamente justo

      Completely Fair Scheduler (CFS) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Clase de planificación normal de Linux orientada a repartir tiempo de CPU según pesos y tiempo de ejecución virtual. Las versiones históricas seleccionaban la menor vruntime; los núcleos recientes emplean EEVDF dentro de la clase fair para la selección basada en elegibilidad y desfase virtual.

      Rol operativo / utilidad

      Equilibra tareas interactivas y por lotes sin un cuanto fijo universal, incorpora pesos nice y grupos, y busca acotar el desfase de servicio entre ejecutables.

      Cita APA

      The Linux Kernel Documentation (s. f.). The Linux kernel documentation (documento «CFS Scheduler» y documento «EEVDF Scheduler», secciones de diseño y vruntime). kernel.org.

      108. Afinidad de CPU

      CPU affinity · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Restricción que define el conjunto de CPUs sobre las que una tarea puede ejecutarse, expresado en Linux mediante una máscara y interfaces como sched_setaffinity. No reserva por sí mismo una CPU ni impide que otras tareas la utilicen.

      Rol operativo / utilidad

      Puede preservar localidad de caché y aislar cargas, pero reduce las opciones de equilibrio y puede dejar una tarea esperando pese a CPUs libres no permitidas.

      Cita APA

      Kerrisk, M. (2010). The Linux programming interface: A Linux and UNIX system programming handbook (cap. 35, «Process Priorities and Scheduling», §35.4, «CPU Affinity»). No Starch Press.

      109. Núcleos de rendimiento y eficiencia

      Performance cores and Efficient cores (P-cores / E-cores) · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Clases de núcleos en una arquitectura heterogénea: los P-cores priorizan alto desempeño por hilo y los E-cores eficiencia y densidad. Difieren en capacidad, frecuencia y rasgos, por lo que una CPU libre no siempre es intercambiable con otra.

      Rol operativo / utilidad

      El planificador debe colocar cada hilo según demanda, capacidad y objetivos energéticos; una mala migración puede degradar latencia o consumo pese a equilibrar conteos.

      Intel Corporation (s. f.). Intel® 64 and IA-32 architectures software developer’s manual (vol. 3A, cap. 8, «Multiple-Processor Management»; documentación de arquitecturas híbridas aplicable). Intel.

      Throughput · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Cantidad de trabajo completado por unidad de tiempo, expresada, por ejemplo, en procesos terminados por segundo o solicitudes atendidas por segundo. Debe especificarse la unidad, la carga y los criterios de finalización para que la medida sea comparable.

      Rol operativo / utilidad

      Evalúa capacidad útil del sistema y efectos de planificación o E/S; puede aumentar mientras empeora la latencia individual, por lo que se analiza junto con percentiles y utilización.

      111. Tiempo de retorno

      Turnaround time · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Intervalo desde la llegada o sumisión de un trabajo hasta su finalización. Incluye ejecución, esperas en colas y demás demoras del ciclo de vida, por lo que no equivale al tiempo consumido en CPU.

      Rol operativo / utilidad

      Mide cuánto tarda el sistema en completar un trabajo y permite comparar políticas de planificación, especialmente en cargas por lotes.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.2, «Scheduling Criteria»). Wiley.

      112. Tiempo de espera

      Waiting time · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Suma de los periodos que una tarea pasa lista sin ocupar la CPU bajo el modelo clásico de planificación. No incluye su ejecución ni, salvo definición distinta del ejercicio, el tiempo bloqueado por E/S.

      Rol operativo / utilidad

      Aísla el costo de competir por procesador y ayuda a evaluar equidad, efecto convoy y consecuencias de cuantos o prioridades.

      113. Tiempo de respuesta

      Response time · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      En planificación interactiva, tiempo desde que se formula una solicitud hasta que el sistema produce su primera respuesta, no hasta completar toda la operación. En servicios debe precisarse si se mide en cliente o servidor y qué evento marca el inicio.

      Rol operativo / utilidad

      Captura la percepción inicial de interactividad; RR, prioridades y control de colas lo influyen, y una media debe complementarse con percentiles.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.2, «Scheduling Criteria»). Wiley.

      Gantt chart · Módulo 2: Procesos, hilos, sincronización y CPU

      Definición formal

      Representación temporal con una barra por intervalo de ejecución que muestra qué proceso ocupa la CPU y cuándo ocurren las conmutaciones. En ejercicios se acompaña de llegadas, ráfagas y cuantos para derivar espera y retorno.

      Rol operativo / utilidad

      Hace verificable una simulación de planificación y evidencia apropiaciones, periodos ociosos y efecto convoy sin sustituir los cálculos de métricas.

      115. Memoria física

      Physical memory · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Almacenamiento direccionable instalado en el sistema, principalmente RAM, al que el procesador accede mediante direcciones físicas después de la traducción y de los mecanismos de interconexión. El núcleo administra marcos libres, asignados y reservados.

      Rol operativo / utilidad

      Definición formal

      Abstracción que separa las direcciones usadas por los programas de la memoria física y permite espacios protegidos, mapeos de archivos y residencia parcial mediante paginación bajo demanda. El espacio direccionable puede exceder la RAM disponible, sujeto a límites y almacenamiento de respaldo.

      Aísla procesos, simplifica asignación y carga, comparte páginas y utiliza disco o compresión como extensiones; a cambio introduce traducción y fallos de página.

      117. Espacio de direcciones lógico

      Logical address space · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Conjunto de direcciones generadas por el programa y su procesador antes de convertirse en ubicaciones físicas. En el modelo paginado general se identifica con el espacio virtual; en x86, una dirección lógica pasa primero por segmentación para producir una dirección lineal.

      Rol operativo / utilidad

      Proporciona a cada proceso una vista propia y reubicable del almacenamiento; el núcleo define sus regiones y la MMU valida cada traducción.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.1.3, «Logical versus Physical Address Space»). Wiley.

      118. Unidad de gestión de memoria

      Memory Management Unit (MMU) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Componente de hardware que traduce direcciones virtuales a físicas usando TLB y tablas de páginas y comprueba permisos como escritura, usuario y ejecución. Ante una traducción o acceso no válido genera una excepción para el núcleo.

      Rol operativo / utilidad

      Hace cumplir aislamiento y memoria virtual en cada referencia sin intervención de software en el caso favorable; coopera con el manejador de fallos para resolver excepciones.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3.2, «Hardware Support»). Wiley.

      119. Registro base y límite

      Base and limit registers · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Par de registros usado en esquemas simples de reubicación: el base se suma a la dirección lógica y el límite delimita el rango permitido. El hardware compara cada referencia antes de permitir el acceso a memoria física.

      Rol operativo / utilidad

      Ofrece reubicación y protección básicas para particiones contiguas, pero no resuelve por sí solo la fragmentación externa ni la flexibilidad de la paginación moderna.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.1.1, «Basic Hardware»). Wiley.

      120. Paginación

      Paging · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Método que divide la memoria virtual en páginas y la física en marcos del mismo tamaño, relacionados por tablas de páginas. Las páginas de un proceso no necesitan ocupar marcos contiguos y pueden cargarse bajo demanda.

      Rol operativo / utilidad

      Elimina la fragmentación externa de la asignación por páginas, facilita intercambio y compartición y deja la traducción y protección por página a la MMU.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3, «Paging»). Wiley.

      121. Página virtual

      Virtual page · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Bloque de tamaño fijo del espacio de direcciones virtuales que constituye la unidad básica de mapeo y protección. Su número y desplazamiento se obtienen de la dirección; puede estar respaldada por un marco, un archivo, swap o una página cero.

      Rol operativo / utilidad

      Permite administrar residencia y permisos con granularidad uniforme; su tamaño influye en fragmentación interna, costo de tablas y alcance del TLB.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3, «Paging»). Wiley.

      122. Marco de página

      Page frame · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Bloque de memoria física del mismo tamaño que una página virtual, disponible para alojar su contenido. El núcleo mantiene estado de cada marco para saber si está libre, asignado, compartido, sucio o sujeto a recuperación.

      Rol operativo / utilidad

      Es la unidad real de asignación y reemplazo; una gestión insuficiente de marcos provoca recuperación, escrituras de respaldo y posible hiperpaginado.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3, «Paging»; cap. 10, §10.5). Wiley.

      123. Tabla de páginas

      Page table · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Estructura de datos que registra la correspondencia entre páginas virtuales y marcos, junto con atributos de acceso. Puede organizarse en varios niveles y cada espacio de direcciones dispone de las tablas que describen sus mapeos.

      Rol operativo / utilidad

      Suministra a la MMU la información de traducción y protección; el núcleo la actualiza al mapear, desalojar, compartir o cambiar permisos de páginas.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3; §9.4, «Structure of the Page Table»). Wiley.

      124. Entrada de tabla de páginas

      Page-table entry (PTE) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Registro individual de una tabla que contiene, cuando la traducción es válida, la ubicación del marco y bits de control y estado. Según arquitectura incluye presencia, lectura/escritura, usuario/supervisor, acceso, modificación, caché y no ejecución.

      Rol operativo / utilidad

      Codifica las reglas que la MMU aplica por página y la información que el núcleo necesita para CoW, reemplazo y contabilidad.

      Intel Corporation (s. f.). Intel® 64 and IA-32 architectures software developer’s manual (vol. 3A, cap. 4, «Paging», §4.5, «4-Level Paging and 5-Level Paging»). Intel.

      125. Bit de presencia

      Present bit · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Bit de una entrada de paginación que indica si la entrada puede usarse para traducir una dirección presente en memoria según las reglas de la arquitectura. En x86, si está a cero durante un recorrido, el procesador genera page fault; los bits restantes pueden ser usados por software.

      Rol operativo / utilidad

      Distingue mapeos residentes de páginas bajo demanda o desalojadas y entrega al núcleo la oportunidad de traer contenido o rechazar un acceso inválido.

      Intel Corporation (s. f.). Intel® 64 and IA-32 architectures software developer’s manual (vol. 3A, cap. 4, «Paging», formato de entradas; cap. 6, excepción #PF). Intel.

      126. Bit de suciedad

      Dirty bit · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Indicador de que una página fue modificada desde un punto de referencia, como su carga o la última limpieza. Si una página está limpia y conserva una copia válida de respaldo, puede descartarse sin reescribir su contenido.

      Rol operativo / utilidad

      Reduce E/S durante reemplazo y writeback: solo las páginas sucias necesitan copiarse a archivo o swap antes de reutilizar su marco.

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4, «Page Replacement»). Wiley.

      127. Bit de referencia

      Referenced / accessed bit · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Bit que el hardware activa cuando una página es referenciada, según las reglas de la arquitectura. El software puede limpiarlo periódicamente para aproximar la recencia de uso sin registrar una marca temporal completa por acceso.

      Rol operativo / utilidad

      Alimenta algoritmos como reloj y segunda oportunidad para escoger víctimas frías y aproximar LRU con bajo costo de hardware y software.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4.5, «Enhanced Second-Chance Algorithm»). Wiley.

      128. Tabla de páginas multinivel

      Multilevel page table · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Jerarquía de tablas en la que partes del número de página seleccionan entradas sucesivas hasta llegar a la PTE final. Las ramas correspondientes a regiones no mapeadas no necesitan estar materializadas, aunque cada acceso sin TLB puede requerir varios pasos.

      Rol operativo / utilidad

      Representa espacios grandes y dispersos sin una tabla lineal completa; el TLB amortigua el costo de recorrer sus niveles.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.4.1, «Hierarchical Paging»). Wiley.

      129. Búfer de traducción anticipada

      Translation Lookaside Buffer (TLB) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Caché pequeña y rápida que almacena traducciones recientes de página y sus atributos. Algunas TLB usan identificadores de espacio de direcciones para conservar entradas entre procesos; el núcleo debe invalidar entradas cuando cambia un mapeo.

      Rol operativo / utilidad

      Evita recorrer tablas en la mayoría de accesos y resulta decisivo para la latencia; su alcance mejora con localidad y páginas grandes.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3.2, «Hardware Support»). Wiley.

      130. Acierto de TLB

      TLB hit · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Caso en el que la TLB contiene una traducción válida para la página y el contexto solicitados, con permisos compatibles. El procesador obtiene el marco sin realizar un recorrido completo de las tablas de páginas.

      Rol operativo / utilidad

      Reduce la sobrecarga de memoria virtual a una búsqueda rápida y favorece el rendimiento de cargas con buena localidad de traducción.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3.2, «Hardware Support»). Wiley.

      131. Fallo de TLB

      TLB miss · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Caso en el que la TLB no contiene la traducción requerida y el hardware o software debe consultar las tablas de páginas. Si la PTE es válida se rellena la TLB; si no lo es, se produce un page fault, por lo que ambos eventos no son equivalentes.

      Rol operativo / utilidad

      Añade el costo del recorrido de tablas y puede expulsar otra traducción; una alta tasa sugiere gran conjunto de trabajo de direcciones o poco alcance de TLB.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3.2, «Hardware Support»). Wiley.

      132. Fallo de página

      Page fault · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Excepción generada cuando una referencia no puede completarse por una traducción no presente o por una violación de protección. Puede ser legítima —carga bajo demanda, CoW o acceso a swap— o inválida, en cuyo caso el núcleo entrega un error o señal.

      Rol operativo / utilidad

      Activa la memoria virtual perezosa y la protección; una frecuencia excesiva de fallos que exigen E/S degrada drásticamente el rendimiento.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.2, «Demand Paging»). Wiley.

      133. Rutina de fallo de página

      Page-fault handler · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Código del núcleo que analiza dirección, causa y mapeo asociado a una excepción de página. Si el acceso es válido obtiene un marco, lee o construye el contenido, actualiza las tablas y reanuda; si no, termina la operación o notifica al proceso.

      Rol operativo / utilidad

      Materializa páginas, resuelve CoW y swap y aplica la frontera entre accesos legítimos y violaciones de memoria, manteniendo consistente el espacio de direcciones.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.2.1, «Basic Concepts»). Wiley.

      134. Fragmentación interna

      Internal fragmentation · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Espacio desperdiciado dentro de una unidad ya asignada porque el objeto no ocupa toda su capacidad. Con páginas de tamaño fijo aparece, por ejemplo, en la última página de una región cuyo tamaño no es múltiplo de la página.

      Rol operativo / utilidad

      Reduce memoria útil aunque exista capacidad dentro de asignaciones; influye en la elección del tamaño de página y en el uso de páginas grandes.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.3.1, «Basic Method»). Wiley.

      135. Fragmentación externa

      External fragmentation · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Situación en la que existe memoria libre total suficiente, pero distribuida en huecos no contiguos demasiado pequeños para una solicitud contigua. Es característica de particiones variables y de ciertas asignaciones físicas contiguas.

      Rol operativo / utilidad

      Puede impedir reservas pese a memoria agregada disponible; la paginación ordinaria la evita al no exigir marcos contiguos para páginas virtuales consecutivas.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.2.3, «Fragmentation»). Wiley.

      136. Compactación

      Memory compaction · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Reubicación de contenido para reunir huecos libres y obtener regiones contiguas mayores. Exige actualizar referencias o traducciones y poder mover los objetos; en memoria de usuario paginada no se usa para unir espacios virtuales como en particiones variables.

      Rol operativo / utilidad

      Mitiga fragmentación externa y facilita asignaciones contiguas, pero consume CPU, E/S y sincronización; ciertas páginas no son movibles.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.2.3, «Fragmentation»). Wiley.

      137. Segmentación

      Segmentation · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Esquema que representa la memoria como segmentos lógicos de longitud variable, como código, datos o pila, cada uno con base, límite y atributos. Una dirección contiene selector o número de segmento y desplazamiento.

      Rol operativo / utilidad

      Alinea protección y compartición con unidades lógicas del programa, pero la asignación física variable puede producir fragmentación externa.

      Cita APA

      Tanenbaum, A. S., & Bos, H. (2015). Modern operating systems (4.ª ed.; cap. 3, «Memory Management», §3.7, «Segmentation»). Pearson.

      138. Segmentación paginada

      Paged segmentation · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Modelo combinado en el que el espacio se organiza lógicamente en segmentos y cada segmento se divide en páginas para su asignación física. La traducción atraviesa primero la descripción del segmento y después la tabla de páginas correspondiente.

      Rol operativo / utilidad

      Conserva abstracciones y permisos por segmento mientras elimina la necesidad de que cada segmento sea físicamente contiguo; aumenta la complejidad de traducción.

      Cita APA

      Tanenbaum, A. S., & Bos, H. (2015). Modern operating systems (4.ª ed.; cap. 3, «Memory Management», §3.7, «Segmentation»). Pearson.

      139. Espacio de intercambio

      Swap space · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Almacenamiento secundario o dispositivo lógico utilizado para conservar páginas anónimas desalojadas de RAM y, en algunos sistemas, otros datos de respaldo. Puede residir en partición, archivo o dispositivo comprimido como zRAM, con costos muy distintos.

      Rol operativo / utilidad

      Extiende la capacidad efectiva y permite recuperar memoria bajo presión; su latencia hace que depender continuamente de él empobrezca la ejecución.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 9, «Main Memory», §9.5; cap. 11, «Mass-Storage Structure», §11.6). Wiley.

      140. Hiperpaginado

      Thrashing · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Estado de actividad intensa de paginación en el que los procesos no disponen de suficientes marcos para sus conjuntos activos y expulsan repetidamente páginas que volverán a necesitar. La CPU puede quedar infrautilizada mientras el sistema atiende E/S de memoria.

      Rol operativo / utilidad

      Convierte la recuperación de páginas en cuello de botella dominante; se controla reduciendo multiprogramación, ajustando memoria o aplicando límites y modelos de working set.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.6, «Thrashing»). Wiley.

      141. Conjunto de trabajo

      Working set · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Aproximación al conjunto de páginas que un proceso ha usado recientemente dentro de una ventana de referencias o tiempo. Representa su localidad actual y cambia entre fases de ejecución; no equivale al tamaño total de su espacio virtual.

      Rol operativo / utilidad

      Estima cuántos marcos necesita una carga para ejecutar sin paginación excesiva y orienta asignación, control de multiprogramación y detección de thrashing.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.6.2, «Working-Set Model»). Wiley.

      142. Reemplazo óptimo

      Optimal page replacement (OPT) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Algoritmo teórico que expulsa la página cuya próxima referencia ocurrirá más lejos en el futuro. Minimiza fallos para una secuencia conocida, pero requiere información futura que un sistema operativo real no posee.

      Rol operativo / utilidad

      Sirve como cota inferior de fallos y patrón para evaluar algoritmos prácticos; no es una política implementable sin predicción perfecta.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4.3, «Optimal Page Replacement»). Wiley.

      143. Reemplazo FIFO

      First-In, First-Out page replacement · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Algoritmo que reemplaza la página residente desde hace más tiempo según su orden de carga, usando una cola. No considera referencias posteriores, por lo que una página antigua y muy utilizada puede ser elegida.

      Rol operativo / utilidad

      Es barato y simple, pero puede producir más fallos que políticas basadas en uso y está sujeto a la anomalía de Belady.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4.2, «FIFO Page Replacement»). Wiley.

      144. Anomalía de Belady

      Belady's anomaly · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Fenómeno por el que ciertos algoritmos, entre ellos FIFO, generan más fallos al aumentar el número de marcos para una misma secuencia. Contradice la intuición de que más memoria siempre mejora cualquier política; los algoritmos de pila como LRU no la presentan.

      Rol operativo / utilidad

      Demuestra que el rendimiento de reemplazo no siempre varía monótonamente con memoria y obliga a validar algoritmos con trazas, no solo con intuición.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4.2, «FIFO Page Replacement»). Wiley.

      145. Uso menos reciente

      Least Recently Used (LRU) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Política que reemplaza la página cuya última referencia es más antigua, basándose en que la recencia aproxima la probabilidad de uso futuro. La implementación exacta exige registrar orden de accesos y suele aproximarse con bits, contadores o listas muestreadas.

      Rol operativo / utilidad

      Explota localidad temporal y evita la anomalía de Belady en su forma de pila; su costo y precisión dependen de la aproximación elegida.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4.4, «LRU Page Replacement»). Wiley.

      146. Algoritmo del reloj

      Clock page-replacement algorithm · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Aproximación de segunda oportunidad que recorre páginas circularmente: si el bit de referencia está activo lo limpia y avanza; si está inactivo selecciona esa página como víctima. Variantes consideran también el bit de suciedad.

      Rol operativo / utilidad

      Aproxima LRU con estructuras simples y bajo costo por acceso, equilibrando calidad de selección y sobrecarga del núcleo.

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4.5, «Second-Chance Algorithm»). Wiley.

      147. Uso menos frecuente

      Least Frequently Used (LFU) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Política que selecciona para reemplazo la página con menor número de referencias en un periodo o desde su carga. La frecuencia histórica puede conservar páginas que fueron populares pero ya no pertenecen a la localidad actual.

      Rol operativo / utilidad

      Puede identificar páginas frías en cargas estables, pero necesita contadores y envejecimiento para evitar que el pasado domine indefinidamente las decisiones.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4.6, «Counting-Based Page Replacement»). Wiley.

      148. Uso más frecuente

      Most Frequently Used (MFU) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Política experimental que expulsa la página con mayor conteo de referencias, apoyándose en la hipótesis de que una página con poca frecuencia pudo haber llegado recientemente y aún ser necesaria. No suele ofrecer buen comportamiento general.

      Rol operativo / utilidad

      Ilustra que frecuencia y utilidad futura no son equivalentes; se emplea principalmente para comparación teórica, no como política dominante de sistemas reales.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 10, «Virtual Memory», §10.4.6, «Counting-Based Page Replacement»). Wiley.

      149. Direccionamiento x86-64

      x86-64 addressing · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Modelo de direcciones virtuales canónicas de x86-64 que utiliza paginación de cuatro niveles con 48 bits o, con LA57, cinco niveles y 57 bits. Los bits superiores deben extender correctamente el bit significativo y los tamaños habituales incluyen 4 KiB, 2 MiB y 1 GiB.

      Define cómo la MMU descompone direcciones y recorre tablas; los bits canónicos, permisos y niveles determinan qué mapeos son válidos y cómo se protegen.

      Intel Corporation (s. f.). Intel® 64 and IA-32 architectures software developer’s manual (vol. 3A, cap. 4, «Paging», §4.5, «4-Level Paging and 5-Level Paging»). Intel.

      150. PML4

      Page Map Level 4 (PML4) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Nivel superior de las tablas de paginación x86-64 de cuatro niveles. Su tabla contiene 512 entradas que seleccionan tablas PDPT; con páginas de 4 KiB, cada entrada cubre una región virtual de 512 GiB.

      Rol operativo / utilidad

      Es la raíz del recorrido de traducción en modo de cuatro niveles; el registro CR3 localiza la tabla activa y cambia el contexto de direcciones.

      Intel Corporation (s. f.). Intel® 64 and IA-32 architectures software developer’s manual (vol. 3A, cap. 4, «Paging», §4.5, «4-Level Paging»). Intel.

      151. PML5

      Page Map Level 5 (PML5) · Módulo 3: Gestión y virtualización de memoria

      Definición formal

      Nivel raíz adicional introducido por LA57 para la paginación x86-64 de cinco niveles. Contiene 512 entradas que referencian tablas PML4 y amplía el espacio virtual canónico a 57 bits sin alterar el tamaño básico de página.

      Rol operativo / utilidad

      Paravirtualization · Módulo 5: Virtualización, contenedores y operación

      Definición formal

      Modelo en el que el invitado coopera explícitamente con el hipervisor mediante hiper llamadas o interfaces virtuales en lugar de depender siempre de la captura de instrucciones sensibles. Puede exigir adaptar el núcleo invitado o instalar controladores paravirtualizados.

      Rol operativo / utilidad

      Reduce operaciones costosas y mejora E/S al compartir una interfaz conocida, pero acopla invitado e hipervisor y requiere soporte en ambos.

      Rol operativo / utilidad

      295. Sistema operativo de tiempo real

      Real-Time Operating System (RTOS) · Módulo 6: Seguridad, IPC, gráficos y plataformas

      Definición formal

      Sistema diseñado para ejecutar tareas con requisitos temporales verificables, ofreciendo planificación, sincronización e interrupciones con latencias acotadas. Tiempo real significa cumplir plazos, no simplemente responder rápido ni alcanzar el máximo throughput.

      Rol operativo / utilidad

      Prioriza previsibilidad y permite analizar el peor caso de tareas periódicas o reactivas; controla bloqueos, prioridades y temporizadores para evitar sobrepasar deadlines.

      Cita APA

      296. Determinismo temporal

      Temporal determinism · Módulo 6: Seguridad, IPC, gráficos y plataformas

      Definición formal

      Propiedad por la que una operación presenta un comportamiento temporal acotado y repetible dentro de tolerancias especificadas, incluido el peor caso y la variación o jitter. Requiere analizar hardware, caches, interrupciones, planificación y recursos compartidos.

      Rol operativo / utilidad

      Permite demostrar que una tarea cumple su plazo y reduce sorpresas bajo carga; una latencia media baja no basta si existe una cola de bloqueo ilimitada.

      Cita APA

      Barry, R. (2016). Mastering the FreeRTOS real time kernel: A hands-on tutorial guide (cap. 3, «Task Management», planificación; cap. 7, «Resource Management»). Real Time Engineers Ltd..

      297. FreeRTOS

      FreeRTOS · Módulo 6: Seguridad, IPC, gráficos y plataformas

      Definición formal

      Núcleo de tiempo real pequeño y portable para microcontroladores que ofrece tareas, colas, semáforos, temporizadores y planificación, con configuración estática o dinámica de memoria. No es un sistema UNIX completo; su API y servicios se centran en aplicaciones embebidas.

      Rol operativo / utilidad

      Planifica tareas con prioridades y proporciona IPC y sincronización acotados en dispositivos con recursos limitados, bajo una configuración conocida por el desarrollador.

      Cita APA

      Barry, R. (2016). Mastering the FreeRTOS real time kernel: A hands-on tutorial guide (cap. 1, «The FreeRTOS Distribution»; cap. 3, «Task Management»). Real Time Engineers Ltd..

      298. Tiempo real estricto

      Hard real-time · Módulo 6: Seguridad, IPC, gráficos y plataformas

      Definición formal

      Clase de sistema en la que superar un plazo se considera un fallo de corrección, no solo una pérdida de calidad. La garantía exige acotar tiempo de ejecución en peor caso, interferencias, bloqueos y respuesta a eventos bajo supuestos explícitos.

      Rol operativo / utilidad

      Obliga a diseñar planificación y recursos para el peor caso y a validar todos los caminos críticos; optimizar promedios no demuestra seguridad temporal.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.5, «Real-Time CPU Scheduling»). Wiley.

      299. Tiempo real flexible

      Soft real-time · Módulo 6: Seguridad, IPC, gráficos y plataformas

      Definición formal

      Clase de sistema en la que cumplir plazos es deseable y los incumplimientos reducen utilidad o calidad, pero no constituyen por definición un fallo catastrófico. Audio, vídeo e interacción pueden tolerar degradación limitada según requisitos.

      Rol operativo / utilidad

      El planificador favorece tareas sensibles a latencia mientras se aceptan ocasionales pérdidas acotadas; se evalúan distribuciones y plazos además del promedio.

      Cita APA

      Silberschatz, A., Galvin, P. B., & Gagne, G. (2018). Operating system concepts (10.ª ed.; cap. 5, «CPU Scheduling», §5.5, «Real-Time CPU Scheduling»). Wiley.

      300. Bloqueos de activación

      Wakelocks · Módulo 6: Seguridad, IPC, gráficos y plataformas

      Definición formal

      Mecanismos de Android y Linux que impiden que el sistema o componentes entren en suspensión mientras una tarea declara trabajo pendiente. Pueden solicitarse desde espacio de usuario mediante APIs o mantenerse en el núcleo; deben liberarse al terminar para recuperar ahorro energético.

      Rol operativo / utilidad
